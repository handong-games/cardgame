# 디자인 설계도 운영 인덱스 v6.0

> 이 문서는 gamedesign의 세분화된 설계도 관리 구조를 정의한다.
> v5.0을 대체한다.
> **최종 수정일**: 2026-03-16

---

## 1. 목적

- 디자인 자산을 카테고리별로 쪼개서 관리한다.
- 스타일 원칙, 프롬프트, 실제 제작, QA가 같은 구조를 바라보게 만든다.
- 문서와 실제 프롬프트가 함께 움직이도록 변경 순서를 고정한다.

## 5. 설계도 단위 체크리스트

| 항목 | 확인 질문 |
|------|-----------|
| 역할 | 이 모듈이 담당하는 플레이 경험이 명확한가? |
| 입력 | gameplan과 어떤 필드를 연결하는가? |
| 출력 | 프롬프트, 이미지, UI에서 무엇이 만들어지는가? |
| 규칙 | DNA/에센스 중 어떤 제약을 직접 받는가? |
| QA | 어떤 실패 패턴을 반복적으로 확인해야 하는가? |

---

## 6. 운영 원칙

- 하나의 변경은 반드시 **DNA / 에센스 / 프롬프트 / 설계도** 중 어디에 속하는지 먼저 정한다.
- 카테고리 문서는 설명이 아니라 **관리 단위**로 유지한다.
- 장르 감성보다 전투 가독성과 정보 구조를 우선한다.
- 문서 예시가 실제 프롬프트와 다르면 문서를 수정한다.

---

## 7. 권장 관리 루틴

1. 주간 기준 문서 점검 (`DNA`, `에센스`)
2. 프롬프트 변경 직후 동기화 점검 (`promptExamples.ts`, `PROMPT-EXAMPLES.md`)
3. 에셋 생성 직후 카테고리 설계도 QA
4. gameplan 업데이트 직후 전 모듈 영향도 확인
