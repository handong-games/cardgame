## Phase 0: 기준 정비 및 운영 체계 확립 ⬅ 현재

> **목표**: v5.0 기준을 단일 운영 원칙으로 고정하고, 문서/프롬프트/설계도가 함께 움직이는 체계를 만든다.

### 0-1. v5.0 기준 통일

| 작업 | 목표 |
|------|------|
| 활성 스타일 기준 통일 | 모든 운영 문서의 기준 버전을 v5.0으로 고정 |
| 문서 권위 체계 정리 | gameplan → promptExamples.ts → DNA → 운영 문서 순으로 명확화 |
| 레거시 표현 제거 | v4.0을 활성 기준처럼 읽히는 문구 제거 |

### 0-2. 문서-프롬프트 동기화 체계 확립

1. 엔티티 프롬프트 변경은 `src/data/promptExamples.ts`에서 먼저 수행
2. 변경 직후 `docs/PROMPT-EXAMPLES.md`와 관련 설계 문서를 동기화
3. 스타일 원칙 변경은 `docs/비주얼-디자인-DNA-v5.md`와 에센스 문서에서 먼저 정의
4. 구조 변경은 설계도 운영 문서에 먼저 반영

### 0-3. 디자인 관리 문서 세분화

| 문서 | 역할 |
|------|------|
| `docs/비주얼-디자인-DNA-v5.md` | 최상위 시각 원칙 |
| `docs/디자인-에센스-v5.md` | 게임 디자인의 감정/가독성/미학 핵심 축 |
| `docs/디자인-설계도-운영-인덱스-v5.md` | 캐릭터/몬스터/프레임/배경/UI/이펙트/씬 관리 구조 |
| `docs/PROMPT-EXAMPLES.md` | 실전 예시와 운영용 레퍼런스 |

### 에셋 생성 워크플로우

```
[1] gameplan 검증
    - Tier 1 / Tier 2 문서 확인
    - designStatus 확인

[2] 프롬프트 검증
    - promptExamples.ts 확인
    - DNA/에센스/설계도 기준 대조

[3] 생성
    - Claude 커맨드 또는 수동 프롬프트 실행

[4] QA
    - PROMPT-EXAMPLES 체크리스트 대조
    - 전투 가독성 / 방향 / 톤 / 위협도 검증

[5] 저장 및 기록
    - assets 저장
    - meta 기록
    - TODO 갱신
```
